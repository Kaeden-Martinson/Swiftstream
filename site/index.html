Keep your SSH login. Lose the slow transfers.

Swiftstream uses SSH once to start itself on your server. After that, files move over HTTPS on eight connections at once, and anything unchanged is skipped.

Download for Windows

Works with any Linux or macOS server you can SSH into. Swiftstream installs itself there, and Node.js if it's missing.

01 · why it's faster

A dropped packet shouldn't stall the whole transfer.

Thousands of small files, a few requests

SFTP waits for a reply on every file it opens. Swiftstream packs small files into bundles of up to 8 MB and sends several at once.

Unchanged files stay put

Folders are compared by size and timestamp first, so a redeploy only sends what changed.

Measure it on your own connection:

$ swiftstream bench prod

02 · how it works

One SSH login, then you're done with it.

  1. Log in the way you already do

    Swiftstream runs your normal ssh once and starts itself on the server.

  2. Your key is authorized, the server is pinned

    Its certificate arrives over that SSH session, so there's no "trust this host?" guesswork.

  3. Connect from the app or the terminal

    Shells and transfers go over HTTPS from then on.

04 · security

Same trust model as SSH. Standard crypto only.

Servers are pinned like known_hosts, and logins use a key that never leaves your computer. None of the cryptography is home-made.

server identity
Each server has its own certificate. If its fingerprint ever changes, Swiftstream refuses to connect.
your key
Ed25519, generated on your computer. Servers only ever see the public half.
transport
TLS from Node and OpenSSL. Every chunk and every file is checked with SHA-256.
access
Only keys listed in the server's authorized_keys file can log in, and repeated failed logins are blocked for 10 minutes.
How the login works

The server sends a random challenge. The app signs it together with that server's certificate fingerprint, so the signature is useless to any other server. You get a session that expires after 12 hours.
